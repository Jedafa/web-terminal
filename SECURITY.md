# SECURITY.md — модель угроз и защита

Разбор того, как Web Terminal защищён от популярных (OWASP Top 10 2025) и
менее известных уязвимостей. Каждому пункту соответствует код в `server.mjs`.

## Популярные уязвимости (OWASP Top 10 2025)

| Уязвимость | Как защищено |
|---|---|
| **A01 Broken Access Control** | Без валидной cookie-сессии недоступно всё: WebSocket-рукопожатие отклоняется middleware до создания PTY, `/auth/check` возвращает 401. sessionId валидируется по регулярке, лимит ≤ 16 PTY на IP. |
| **A02 Security Misconfiguration** | Безопасные заголовки на всех ответах, `cors.origin` — только явный allowlist (никаких `*`), пароль в логи не пишется, ошибки не раскрывают стек. |
| **A03 Software Supply Chain Failures** | Всего 3 зависимости (`socket.io`, `node-pty`, `node:util` из stdlib). Фронтенд вендорен в `public/vendor/` — ноль внешних CDN, сборки нет. |
| **A04 Cryptographic Failures** | Пароль сравнивается через `crypto.timingSafeEqual` (constant-time, нет timing-утечки); сессионный токен — 256 бит из `crypto.randomBytes`. |
| **A05 Injection** | Никакого SQL/шаблонов. Shell запускается через белый список `/etc/shells`, клиент не может передать команду запуска. Ввод с клавиатуры идёт в PTY как есть — это и есть терминал. |
| **A06 Insecure Design** | Пароль не хранится на клиенте (сессия — HttpOnly cookie); выход гасит сессию на сервере; срок жизни сессии 12 ч со скользящим продлением. |
| **A07 Authentication Failures** | Rate limit: 8 неудач за 5 мин → блок на 15 мин (429 + Retry-After); tarpit-задержка растёт с каждой неудачей; сессионный токен одноразово генерируется при логине (нет session fixation). |
| **A08 Software/Data Integrity Failures** | Нет автообновлений и внешних скриптов; всё из локального репо. |
| **A09 Logging Failures** | Логируются подключения, дисконнекты, создание/смерть PTY, блокировки брутфорса — без паролей и содержимого терминала. |
| **A10 Mishandling of Exceptional Conditions** | Все `pty.*` вызовы обёрнуты в try/catch; тело запроса ограничено 1 КБ; `maxHttpBufferSize` 1 МБ; кривой JSON → 400. |

## Классические веб-уязвимости

| Уязвимость | Как защищено |
|---|---|
| **XSS** | React-фронт (автоэкранирование) / vanilla-фронт без `innerHTML` для данных терминала; xterm.js рендерит вывод PTY как текст-глифы, не HTML. CSP `default-src 'self'`. |
| **CSRF** | Кука `SameSite=Lax` + обязательный заголовок `X-Requested-With: XMLHttpRequest` (кросс-сайтовая форма его не поставит) + валидация Origin. |
| **Кликджекинг** | `X-Frame-Options: DENY` + CSP `frame-ancestors 'none'`. |
| **Path traversal** | Статика: `normalize()` + проверка префикса `PUBLIC_DIR`. |
| **Command injection** | Shell выбирается только из белого списка; `cols/rows` клампятся числами; sessionId — `[a-zA-Z0-9_-]{6,64}`. |
| **Брутфорс пароля** | См. A07. |
| **Утечка через кеш/реферер** | `Cache-Control: no-store`, `Referrer-Policy: no-referrer`. |

## Непопулярные / продвинутые уязвимости

| Уязвимость | Как защищено |
|---|---|
| **CSWSH — Cross-Site WebSocket Hijacking (CWE-1385)** | Главная угроза WS-приложений: чужая страница открывает WebSocket от имени жертвы (кука летит автоматически). Реальные CVE: Next.js CVE-2025-48068, Apache Zeppelin CVE-2024-51775, MeshCentral CVE-2024-26135, Gitpod CVE-2023-0957. У нас: строгая валидация Origin на рукопожатии + cookie-сессия. |
| **Cookie tossing / session fixation** | Токен генерируется заново при каждом логине (`randomBytes(32)`), имя куки фиксировано, `HttpOnly` — JS не может ни перезаписать, ни прочитать. |
| **Timing-атаки на пароль** | `sha256(a) vs sha256(b)` через `timingSafeEqual` — время ответа не зависит от совпадения. |
| **Флуд/DoS** | Флуд-гард: ≤ 800 событий ввода за 5 с на сокет; лимит PTY на IP; лимит числа сессий в памяти; тело ≤ 1 КБ; `maxHttpBufferSize` 1 МБ. |
| **Host-header инъекция за прокси** | Origin сравнивается с `X-Forwarded-Host`/`Host`, плюс доверенный сигнал `Sec-Fetch-Site: same-origin` (forbidden header name — из JS не подделать). |
| **Сканеры и боты** | Опциональный `WEB_TERMINAL_PATH_PREFIX`: всё вне секретного пути → 404 («пустой сайт» для ботов). |
| **Похищение пароля из браузера** | Пароль нигде не хранится: ни в localStorage, ни в куках — только в памяти формы на пару секунд логина. |
| **Кража cookie через XSS** | `HttpOnly` — document.cookie пуст; CSP режет инлайн-скрипты со сторонних источников. |
| **Эскейп-последовательности в логах** | Вывод PTY в логи не пишется (только факты подключения/выхода) — нет log-injection. |
| **Prototype pollution / десериализация** | Входящий JSON распарсен и использован поэлементно; никаких `merge`/`Object.assign` на пользовательских объектах. |
| **Supply chain (npm)** | Минимум зависимостей; `package-lock.json` в репо; фронтенд вендорен. |

## Остаточные риски (честно)

- **Нет TLS из коробки** — ставьте за Caddy/nginx (конфиги в README). Cookie помечается
  `Secure` автоматически, когда запрос приходит по HTTPS.
- **Пароль в env/консоли** — виден в `ps e` суперпользователю машины. Для параноиков:
  systemd `EnvironmentFile=` с правами 600.
- **Это root-доступ в браузере** — любой, кто знает пароль, выполняет любые команды.
  Держите пароль длинным, включайте секретный префикс, не запускайте от root.

Ответственное раскрытие: заводите issue в репозитории.
